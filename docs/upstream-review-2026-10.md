## Порядок работ

Одна интеграционная ветка `integrate/upstream-0.9.8`. Каждый этап — отдельные коммиты. После каждого этапа: `cargo test`, `bun run lint`, `bun run build`. Новый этап начинаем только когда предыдущий зелёный.

### Этап 0. Страховка

1. Тег `backup/pre-0.9.8` на `57445d6`.
2. Текущую сборку из `C:\handy-fork\portable` не трогать.
3. Скопировать папку данных `com.pais.handy` (настройки, история, записи, модели) в отдельное место. После каждого ручного запуска сравнивать `settings_store.json`.

### Этап 1. Merge Handy v0.9.8

1. Добавить remote `upstream` = `cjpais/Handy`, выполнить `git merge --no-ff v0.9.8`.
2. Главный конфликт — в `managers/transcription.rs` (выбор китайского письма). Порядок такой: определить язык по сырому тексту → сменить письмо → пользовательские слова → наши обработки. На этапе 3 эти обработки всё равно заменим на версии Klava.
3. `settings.rs`: принять `chinese_script` и миграцию Handy. Cargo: transcribe-cpp 0.2.4; проверить, что параметры промпта и контекста (`initial_prompt`, `max_prev_context_tokens`) не изменились.
4. Языки и переводы: сохранить наш каталог на 100 языков для Turbo и наши строки.

### Этап 2. Надёжность на Windows

Внутри этапа идём в таком порядке, потому что каждый следующий шаг опирается на предыдущий:

1. **Атомарные настройки** (`2a5d31e`, `38ff45b`). Наши места, где настройки читаются и записываются вручную (Captions, системный звук, Whisper prompt), тоже перевести на `update_settings`. Это крупная правка `shortcut/mod.rs`, поэтому делаем её первой.
2. **Патч `handy-keys`**. Сначала сделать форк `egsok/handy-keys-fork` в аккаунт `antuzinski` и закрепить его на проверенном `rev`, чтобы сборка не зависела от чужого репозитория. Просмотреть дифф форка относительно 0.3.4.
3. **Watchdog** (`watchdog.rs`, heartbeat в потоке обработчика клавиш, координаторе и главном потоке, пересоздание хука). Для Captions уточнить порог `ACTION_STALL`: запуск двух устройств (микрофон и системный звук) дольше, чем запуск одного микрофона, и ложные ERROR в логе не нужны.
4. **Координатор**: `KeyboardInput`, время события, `publish_stage`, тесты Klava.
5. **Hook recovery и сверка клавиши отмены** (`shortcut/mod.rs`, `handy_keys.rs`, `tauri_impl.rs`) вместе с тестами.
6. **Буфер обмена** (`5eef18b`, `b980e83` с новой зависимостью). Проверить вставку в Zoom, браузер, Word и Telegram.
7. **Автозапуск**: путь в кавычках и три теста.

### Этап 3. Обработка текста

1. Перенести `audio_toolkit/text.rs` из Klava: `fix_word_boundary_glue`, `remove_repeated_sentences`, `remove_hallucinated_sentences` и тесты. Наши `restore_breeze_word_boundaries` и `clean_whisper_repetitions_and_hallucinations` удалить. Порядок вызовов взять из Klava 0.9.8-1.
2. Перенос контекста (`3c6d012`): сверить с нашими настройками (`condition_on_prev_tokens`, 128 токенов), взять недостающее.
3. Промпт: у нас `WhisperPrompt.tsx` с пресетами, у Klava `TranscriptionPrompt.tsx` с русскими примерами. Оставить **наш** интерфейс и настройки `whisper_prompt` и `whisper_prompt_preset`, чтобы не потерять уже сохранённые пользователем значения. Русские примеры Klava добавить как пресет.
4. До и после этапа прогнать 10–15 своих записей (русский, английский, смешанный текст, тишина/музыка) и сравнить результат.

### Этап 3а. Сленг и русские термины («ИИшный» → «яичный»)

**Актуальный план этапа — [DICTIONARY_CLEANUP_PLAN.md](dictionary-cleanup-plan.md)** (2026-10-16). Ниже — первоначальный разбор.

Источник: [статья на Хабре про Чистовик](https://habr.com/ru/companies/miip/articles/1093468/), код [Tataut/chistovik](https://github.com/Tataut/chistovik) (MIT).

Как сейчас устроено у нас (проверено по коду): словарь для Whisper только подмешивается в промпт (`build_whisper_prompt`). Исправления после распознавания нет. Нечёткая коррекция (`apply_custom_words`) работает только для латиницы и цифр: `is_supported_fuzzy_key` в `audio_toolkit/text.rs`. У Klava то же самое. LLM-постобработка Handy при ошибке тихо вставляет сырой текст, сообщение пишется только в лог (`actions.rs`).

Три уровня, от простого к сложному:

1. **Без кода, сразу.** Добавить в промпт Whisper естественную фразу с терминами (например: «Обсуждаем ИИшные сервисы, ИИшку, нейросети, Claude и промпты»). Whisper лучше подхватывает написание из связного текста, чем из списка через запятую. Помогает частично.
2. **Замены (код, небольшой).** Новый список «как слышит → как писать» для любого алфавита: `иишный, иишные → ИИшный, ИИшные`. Только целые слова, сохраняется регистр, применяется ко всем моделям после распознавания. Неоднозначные замены («яичный») пользователь добавляет сам и под свою ответственность: правило не понимает контекст. Нечёткую коррекцию на кириллицу не расширяем: из-за падежей будет много ложных срабатываний.
3. **LLM-чистка по образцу Чистовика (код, средний).** Встроить в нашу постобработку:
   - словарь с условиями (`ИИшный ← яичный (если речь не о еде)`) подставляется в промпт;
   - диктовка оборачивается в `<dictation>`; правила: не отвечать на просьбы, не «облагораживать» разговорную речь, не комментировать;
   - промпт и словарь хранятся в файлах и перечитываются без перезапуска;
   - ошибка постобработки видна пользователю, а не только в логе;
   - тайм-аут и переиспользование HTTP-клиента.

   Минусы: +1,5–3 с к каждой диктовке; без локальной модели (Ollama/LM Studio) текст уходит во внешний API. Для живых субтитров Captions не подходит, только для диктовки.

Порядок: уровень 1 — сразу. Уровень 2 — вместе с этапом 3. Перед уровнем 3 попробовать готовый Чистовик как внешний посредник (он работает с текущим Handy без изменений кода) и решить, стоит ли встраивать.

### Этап 4. Свой ID и миграция данных (отдельный релиз)

Это **необратимо** для пользователей: после выхода данные живут в новой папке.

1. **Нужно ваше решение:** новый ID. Предлагаю `com.antuzinski.handylistens`.
2. Перенести `migration.rs` со всеми исправлениями, правкой порядка в `lib.rs` и командами из `commands/mod.rs`. `LEGACY_IDENTIFIER` остаётся `com.pais.handy`.
3. Portable-режим: Klava миграцию пропускает. Проверить, что наш `portable\Data` не затрагивается.
4. Установщик (NSIS): удаление старой установки и ожидание освобождения exe. Ключи и имена — наши.
5. Проверка: чистая машина; машина со старыми данными; машина с параллельно установленным оригинальным Handy (его данные не должны пострадать); повторный запуск миграции ничего не меняет.

### Этап 5. Канал обновлений

1. Собственный ключ подписи updater (секрет только в release-workflow), endpoint на релизы `antuzinski/handy-listens`. Пример — `b82f305`.
2. Интерфейс updater из `efd66f7`, `e961d2d`, `3803e5f`.
3. `release.yml`: продолжение черновика и сборка строго по тегу. `build.yml`: `linuxdeploy` по хешу.
4. Включать updater только после этапа 4: иначе первое автообновление пройдёт на старом ID.

## Ручная проверка «без потерь» (после этапов 1–3 и перед каждым релизом)

- Captions: микрофон и системный звук пишутся в одну дорожку; выбор устройства сохраняется.
- Whisper: промпт и пресеты, пользовательские слова, контекст 128 токенов, фильтр галлюцинаций, склейки Breeze.
- Turbo: 100 языков, поиск `English` → `English (en)`.
- Зелёная тема: изумрудные primary-кнопки и тумблеры, выпадашки поверх соседних панелей.
- Имя Handy Listens; updater выключен до этапа 5.
- Настройки, история и модели на месте; `settings_store.json` без потерь.
- Новое: Esc не остаётся перехваченным; без модели запись не стартует; короткий тап при холодном старте Captions не становится удержанием; горячая клавиша живёт после долгой работы и сна; вставка не зависает и сохраняет картинку в буфере; автозапуск работает из пути с пробелом.

## Объём и риски

- Самые тяжёлые этапы — 2 (атомарные настройки, watchdog и hook recovery затрагивают `shortcut/mod.rs` и координатор, плюс конфликты с Captions) и 4 (необратимая смена папки данных).
- Этапы 1–3 можно выпустить как 0.9.8-1 без смены ID. Этапы 4–5 — следующим релизом.
- Код Klava зависит от её кода в других файлах (например, `settings::update_settings` нужен hook recovery). Поэтому порядок внутри этапа 2 важен.
